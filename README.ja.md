# ビジネスモデル × 組織アトラス

[English](README.en.md) · [简体中文](README.md) · **日本語** · [한국어](README.ko.md) · [Español](README.es.md) · [Français](README.fr.md)

**ビジネスモデルの選択**と**組織形態・力・変化**をつなぐインタラクティブなアトラスです。
ヘンリー・ミンツバーグ『Understanding Organizations...Finally!: Structure in Sevens』
（Berrett-Koehler、2023）の解釈的フィールドガイドであり、原書の代替ではありません。

創業者、経営者、コンサルタント、学生が「この組織はなぜこう動くのか」「別のモデルに合わせるには
何を変える必要があるのか」を考えるための道具です。

- **アカウント不要、バックエンドなし、解析なし。** すべての計算はブラウザ内で完結します。
- **6 言語。** 英語、简体中文、日本語、한국어、Español、Français を即時に切り替えられます。
- **ビルド不要、依存関係なし。** 素の HTML、CSS、ネイティブ ES Modules だけで動きます。

## ツアー

アトラスには 10 のセクションがあり、最初は「ビジネス→組織」が開きます。

| セクション | できること |
| --- | --- |
| **01 ビジネス→組織** | 顧客・価値・経済・境界の 4 つのモデル操作を選び、どの組織形態に寄るか、どこに緊張が生じるか、何でバランスを取るかを確認します。 |
| **02 キャンバス** | ビジネスモデルの 9 ブロックを組織の視点で順にたどります。 |
| **03 パターン** | アンバンドル、ロングテール、マルチサイド、フリー、オープンの 5 パターンを探ります。 |
| **04 デザイン** | 顧客・提供価値・リソース・財務のどこから設計するかを選び、モデルを組織へ落とし込みます。 |
| **05 事例** | 実在企業の事例を読み、対応する「ビジネス→組織」のシナリオへ直接移動します。 |
| **06 アトラス** | 4 つの基本形態をダイヤモンド図に配置し、3 つの二次形態も確認できます。 |
| **07 形態** | 7 形態それぞれの調整機構、権力パターン、成立条件、リスク、実例を読みます。 |
| **08 力** | 7 つの力をスライダーで動かし、現在寄っている形態と打ち消す力を確認します。 |
| **09 変化** | ライフサイクルの段階と一般的な移行経路をたどります。 |
| **10 概要** | 出典、範囲、方法を確認します。 |

## クイックスタート

静的ファイルを配信するために **Node.js 18+** または **Python 3** だけが必要です。インストールも
ビルドも不要です。

```bash
# 推奨: 依存関係のない同梱 Node サーバー
npm start
```

```bash
# 代替: Python の静的サーバー
python -m http.server 8765 --bind 127.0.0.1
```

<http://127.0.0.1:8765/> を開きます。停止するには `Ctrl+C` を押します。

**なぜローカルサーバーが必要ですか？** アプリはネイティブ ES Modules を使っています。ブラウザは
セキュリティ上の理由から `file://` ページでのモジュール読み込みを拒否するため、
`index.html` をダブルクリックすると空のページやエラーになります。HTTP 経由で開けばコードを変えずに
動作します。

ポート 8765 が使用中の場合:

```bash
PORT=9000 npm start
```

Windows PowerShell では `$env:PORT=9000; npm start` と入力します。

## プロジェクト構成

```text
index.html                  セマンティックなマークアップと唯一のエントリーポイント
package.json                スクリプトのみ。実行時の依存関係なし
styles/                     レイヤーまたはビューごとのスタイルシート
  fonts.css                 ローカル WOFF2 9 書体の @font-face
  tokens.css                色・余白・タイポグラフィの変数
  base.css                  リセット、既定スタイル、見出しの自然な折り返し
  layout.css                ヘッダー、ナビゲーション、言語選択、ビューの外枠
  atlas.css ... overrides.css  ビュー別スタイル（ソース順を維持）
assets/fonts/               Inter、Noto Sans SC/JP/KR のサブセットとライセンス
js/
  app.js                    構成ルート: 初期化、言語制御、ハッシュルーティング
  core/html.js              HTML エスケープと構造図の描画
  i18n/                     言語メタデータ、翻訳辞書、t()、ローカライズ済みラベル
  data/                     純粋なデータ: 形態、力、段階、経路、ブリッジ規則...
  ui/                       ビューごとに 1 モジュール。状態と描画を所有
scripts/
  serve.mjs                 依存関係のないローカル静的サーバー
  audit.mjs                 構造・セキュリティ・アクセシビリティ・データ監査
```

## 仕組み

モジュールは一方向に依存します。

```text
data  ->  i18n  ->  ui  ->  app.js
```

- **`js/data/`** はリーフモジュールです。プレーンなオブジェクトをエクスポートするだけで、何も
  インポートしないため、テスト・差分確認・再利用が容易です。
- **`js/i18n/`** が現在の言語を保持します。翻訳キーはマークアップとデータで使われる英語の原文その
  ものなので、英語用の対応表は不要で、未翻訳時は安全に英語へフォールバックします。
- **`js/ui/`** はビューごとに 1 モジュールです。各モジュールが状態を所有し、`renderXView()` と
  `initXView()` をエクスポートします。ビュー間の操作は狭い API を通します。たとえば他のビューは
  ブリッジ状態を直接書き換えず、`applyBridgePreset()` を呼びます。
- **`js/app.js`** は構成ルートです。モジュールを組み立て、決まった順序で描画し、言語セレクターと
  `#bridge` や `#atlas` などの深いリンクを扱います。

実装上の注意:

- CSS は元のカスケード順で読み込みます。`responsive.css` と `overrides.css` は必ず最後に置きます。
- 永続化するのは `localStorage` の言語設定（`organization-atlas-language`）だけです。読み書きの
  失敗も処理します。
- ナビゲーションは `history.replaceState` を使うため、タブ切り替えでブラウザ履歴が増えません。
- 見出しは言語と画面幅に合わせて自然に折り返します。動きを減らす設定にも対応します。
- Google 検索のガイド付き事例、Canvas の関連要素、シナリオ比較、2つの組織形態の比較を利用できます。事例と比較の状態は現在のページ訪問中のみ保持されます。

## よくある作業

**文言やドメインデータを変える。** `js/data/` の該当ファイル、または `index.html` のテキストを編集
します。データはプレーンなオブジェクトなのでビルドは不要です。

**翻訳を追加・修正する。** 英語の原文（翻訳キー）を探し、`js/i18n/translations.js` の該当言語へ
追加します。少量の追加は、ファイル末尾にある
`Object.assign(translations.<言語>.strings, { ... })` の書き方をそのまま使えます。

**言語を追加する。** `js/i18n/languages.js` にメタデータを追加し、`translations.<言語>` を追加または
代入し、`index.html` の `#language-select` に `<option>` を追加します。

**形態や力を追加する。** 対応するデータモジュールを更新し、UI コントロールを追加し、ブリッジと
モデルプロファイルのデータも拡張します。最後に監査を実行してください。ファイル間の外部キー整合性を
検査します。

## 品質チェック

```bash
npm run audit
```

監査は依存関係なしで次を検証します。

- すべての JavaScript モジュールが構文解析でき、相対パスだけをインポートし、依存グラフに循環がない。
- ページの module スクリプトは外部 1 つだけで、インラインのスクリプト・スタイル・イベントハンドラー・
  `style` 属性がない。
- CSP がデフォルト拒否で、`unsafe-inline` と `unsafe-eval` を含まない。
- スタイルシートの順序が正しく、すべての CSS `url()` と WOFF2 フォントが存在して有効である。
- 要素 ID が一意で、フラグメント・ローカルリンク・外部 HTTPS リンクが安全であり、外部リンクが
  `noopener noreferrer` を使っている。
- JavaScript が参照する DOM ID がすべて HTML に存在する。
- データの外部キーが一致する: 形態、プロファイル、構造図、力、プリセット、ブリッジグループ、
  ブリッジプリセット、緊張ルール、パターン、段階、経路、キャンバスブロック、デザイン中心。
- 主要テキストの配色が 3 つの背景すべてで WCAG AA コントラスト（4.5:1）を満たす。
- 6 言語の README がすべて存在する。

## 安全とプライバシー

- ページは**ネットワークリクエストを一切行わず**、バックエンド、解析、Cookie、フォーム、iframe、
  ユーザーコンテンツの取り込みもありません。
- 永続化されるのは `localStorage` の言語選択だけです。
- 外部の事例・ライセンスリンクは明示的なクリック後にのみ開き、`rel="noopener noreferrer"` を
  使います。
- 動的 HTML テンプレートは翻訳テキストをエスケープします。構造的な SVG 本体は信頼された静的
  ソースデータです。
- CSP はリモートリソースとすべてのデータ接続を遮断します。公開する場合は、Web サーバーまたは CDN
  でレスポンスヘッダーの CSP と `frame-ancestors 'none'` を追加してください。
